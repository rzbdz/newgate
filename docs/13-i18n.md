# 13 · 本地化（i18n）

> 用户可见的文本一律走目录表；源码里写**英文**，中文活在 `lib/i18n/catalogs/zh-Hans.json`。
> 这条从 2026-09-20 起生效，由 `app/i18n_test.go` 与 `make check-i18n` 守着。

## 1. 键就是那句英文（msgid），不是符号

```go
style.Field(i18n.T("Proxy", nil), value)
return i18n.E("no such profile: {name}", i18n.A{"name": name})
```

这是 gettext 的老规矩，选它买到的是**一整类故障的消失**：没有「消息 ID」这层间接，
就没有「键写错了」这回事，也就不需要「常量 ↔ 目录 ↔ 调用点」三方对账那套迟早会
腐坏的机制。代价要说清楚：**改动英文措辞 = 旧译文变孤儿**（`tools/i18n check` 会
报出来，不静默）。需要「同一句话两种译文」时，做法是把英文写得更具体（gettext 的
老办法），而不是引入键。

源语言（`en`）在运行时**不查表**：代码里那句就是最终文本，`T` 只做占位符替换。
所以「默认语言 = 源语言」这条路径是零成本的，输出与加 i18n 之前逐字节相同。

## 2. 两层：叶子 `lib/i18n` + 组件 `modules/locale`

| | 是什么 | 为什么在这 |
| --- | --- | --- |
| `lib/i18n` | 查表、具名占位符、单复数、语言标签匹配、目录的解析与序列化 | **共享叶子**：无状态、无生命周期、没有所有者（同 `lib/style`、`config/paths`）。所以包级 `i18n.T` 是被允许的——capability 那条禁令针对的是「有所有者、要排启动顺序、要撤销」的服务 |
| `modules/locale` | 解析用哪门语言（环境变量 / 配置 / 系统 locale）、把目录装进去、`newgate lang` 命令、status 行与 doctor 体检项 | 有状态、有所有权，是组件。**可摘**：摘掉之后目录为空，每句话原样输出英文，进程照常 |

零第三方依赖是硬约束（内核 CI 跑 `GOPROXY=off go test ./...`），所以没有引
`golang.org/x/text`：这里只做四件事，够用就够。同一把尺子下的先例是 `lib/style`
自研的 East Asian Width 子集。

## 3. 目录文件

```
lib/i18n/catalogs/ledger.json    生成物：源码里有哪些消息、各在哪、带什么实参
lib/i18n/catalogs/zh-Hans.json   译文：键 = 英文原文，值 = 中文
```

```jsonc
// ledger.json —— tools/i18n extract 生成，别手改
{ "messages": { "Proxy": {"where": "modules/cli/diag.go:88"} } }

// zh-Hans.json —— 人写 + 工具追加
{
  "meta": { "language": "zh-Hans", "source": "en", "widths": { "label": 8 } },
  "messages": {
    "Proxy": "代理",
    "Saved {n} file": { "other": "已保存 {n} 个文件", "machine": true }
  }
}
```

- 只有正文的条目写成**裸字符串**；要单复数/备注/机翻标记时才写成对象。
- `meta.widths` 是**版式尺寸**（`style.Field` 的标签列宽等）——宽度是语言数据：
  中文 8 列够，英文 `Requests`/`Takeover` 就不够。
- `machine: true` = 机翻待复核；人工过一遍后改成 `reviewed: true`。
- **磁盘覆盖**：`$NEWGATE_HOME/locale/<tag>.json` 能改内置译文里的任何一条，
  不必重新编译（同 `mappings/` 丢个 `.kv` 就生效那条路子）。

## 4. 语言从哪来

```
NEWGATE_LANG  >  state.json 的 locale.lang  >  LC_ALL → LC_MESSAGES → LANG  >  源语言
```

**为什么配置排在系统 locale 之上**：很多开发者用英文系统却想读中文（反过来也有）。
`LANG` 说的是「这台机器的默认语言」，配置说的是「**我要**读什么」——后者更明确。
代价是 `newgate lang zh-Hans` 在 `LANG=en_US.UTF-8` 的 shell 里可能看不出效果，
所以那条命令**必须把来源打出来**（否则就是最难查的一类「我明明设了」）。
想反过来就调换 `modules/locale/resolve.go` 里那两条的次序——只此一处，有测试钉着。

`zh-Hans`/`zh-Hant` 特判：`zh-CN`/`zh-SG` → 简体，`zh-TW`/`zh-HK`/`zh-MO` → 繁体，
裸 `zh` 按简体。归一化在 `lib/i18n/tag.go`。

## 5. 工作流（一条命令，**只在开发者本地跑**）

```bash
make check-i18n     # 不出网、不花钱：账本是否过期 / 占位符 / 孤儿键 / 中文残留
make i18n-sync      # 调本机网关跑 LLM，把缺的译文补上（翻译不进任何自动化流程）
```

`sync` = 扫源码 → 只翻**新增与缺失**的条目（已有译文一律不动，`reviewed` 的更不动）
→ 校验占位符 → 写回并打 `machine` 标记 → 打印对照表供人复核。

模型固定 `smt-deepseek/deepseek-flash` 且**显式关掉思考**：翻译是机械任务，让它思考
既费 token 又慢，推理内容还会混进译文。工具调的就是用户自己的 newgate 网关——
**它本身就是 newgate 的一个用户**（档位链、fallback、上游怪癖修补照常生效）。

首版中文表**不是机翻**：迁移时把代码里原有的中文原样搬进译文表（那是人写的、
高质量）。机翻工具服务的是**以后新增的英文串**。

### 改了英文措辞怎么办

这是 msgid-as-key 唯一要付的代价，所以给它一条**明确的路**，而不是让每次改措辞都
重新翻一遍：

```bash
# 意思没变、只是换了说法（最常见）：把译文搬过去，不花一次 LLM 调用
go run ./tools/i18n rename "旧的英文原文" "新的英文原文"

# 确实是新句子：sync 会把它当新消息翻，并把孤儿列出来
go run ./tools/i18n sync --lang zh-Hans
```

`rename` 是 gettext 的 msgmerge 的微缩版，区别是**由人指名道姓**：自动模糊匹配会把
「改了个词」和「换了句话」混为一谈，而接错一条译文是静默的错——那正是这套设计
最不愿意有的一类错。搬反了就跑 `rename <新> <旧>` 撤销。

不做 `rename` 会怎样：那条新句子在界面上回落到英文（逐句的，不是整屏），`check`
报一条孤儿（CI 红），直到有人翻它或搬它。**这个中间态是可以接受的**——它是
「看得见的缺」而不是「看不见的错」。

## 6. 棘轮

| 检查 | 拦什么 |
| --- | --- |
| 账本是否过期 | 改了文案没跑 `extract`（同 `genmodules -check` 的套路） |
| 占位符一致 | 译文漏了 `{dir}`——界面上会永远显示 `{dir}` |
| 孤儿键 | 改了英文措辞，旧译文还挂在表里 |
| 禁止清单 | 有人把 `ok`/`warn`/`bad`/`skip`、metrics 名、`state.json` 做成了「文案」 |
| 中文残留 | 非测试源码里又冒出中文字面量（注释不算；豁免清单 `tools/i18n/allowlist.json` **只减不增**，终点是空文件） |

判据只有一份实现（`tools/i18n/check`），内核与发行版共用；CI 里跑 `make check-i18n`，
`app/i18n_test.go` 再包一层（挡「跑过了但没人看输出」）。

## 7. 机器标记绝不进目录

`[proxy]`/`[shape-400]` 这类方括号 tag、metrics 计数器名（`chain.failover`）、
`ok/warn/bad/skip`、落盘 JSON 字段名、HTTP 端点、命令名/flag 名、路径——它们是
**grep 的锚点与协议字段**，翻译它们等于改协议。它们结构上不经过 `i18n.T`，
禁止清单是第二道保险（防手滑）。

日志同理：**散文过 `T`，tag 留在外面**。

```go
log.Printf("[proxy] %s", i18n.T("learned {name} has no count_tokens endpoint", i18n.A{"name": name}))
```

## 8. 发行版怎么带自己的文案

发行版是独立 module，内核不认识它的模块名——所以**谁的东西谁带**：发行版模块把自己的
`locale/catalogs/*.json`（`go:embed`）在 `Start` 里注册给 `modules/locale` 的端口，
装哪些语言成了规格书里的一行。摘掉那个模块，它的译文跟着消失。

## 9. 已知的边界

- **日志语言是写它的那个进程的属性**：daemon 由 CLI 拉起时继承 `NEWGATE_LANG`；
  跨语言切换之后 `newgate logs` 里会看到两种语言的旧行——那是历史记录，不该被改写。
  排障时想要单语：`NEWGATE_LANG=en`。
- **只做 one/other 两级复数**：够这个 CLI 用。真需要第三级的语言（俄语、阿拉伯语）
  再谈——那时该重新想的是要不要引 CLDR，而不是在 `lib/i18n` 里堆特例。
- **`probe --json` 这类机器输出不随语言变**：它们走 `Unstyled()`，是给程序读的。
- **落盘的人话保持「写下它那一刻」的语言**：熔断表的 `reason`（就是 `newgate breaker`
  的 Reason 列）在**摘牌 / 探活失败那一刻**渲染好、写进 `health.json`，之后原样读回。
  2026-09-20 实测：daemon 在中文下写下的行，切到 `NEWGATE_LANG=en` 之后仍显示中文
  ——那一列与其余六列语言不一致。
  它与日志同一条边界（历史记录不该被改写），而且**没有任何判据读这句话**（纯显示；
  归类看的是 `Kind` 与 `ruleToken()` 那两个机器标记）。真要它随语言变，做法与
  Rule / Ledger 那两列完全一样：落盘只存**标记 + 数据**，显示时再渲染——`Status`
  里已经有这个形状的字段了，照着加即可。
