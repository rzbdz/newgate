# 09 · 安全

newgate 的职责是**搬运用户的 API key**。这决定了它的安全基线不能按「本机小工具」来定。

## 1. 威胁模型

| 威胁 | 场景 | 对策 |
| --- | --- | --- |
| 密钥落盘明文 | config 注入把 key 写进 tool 的配置文件，用户 commit 了 dotfiles | 优先 env 注入；config 注入时用「配置文件只写 env 变量名」的手法（[05-tools.md](05-tools.md) §2.2）；sandbox 模式的临时文件放 0700 目录并退出即删 |
| 密钥进日志 | 报错信息、`--verbose`、崩溃栈里带 key | `Secret` 包装类型 + 全局 redaction；CI 里加检测：日志输出中出现 `sk-` 类模式即失败 |
| 密钥被本机其他进程读走 | 网关无鉴权，任何本地程序都能用 | 每 session 短期 token；只监听 loopback |
| 恶意仓库配置 | clone 的仓库带 `.newgate.json`，指向攻击者的 endpoint 偷你的 prompt | 项目级配置只能引用已有 provider，不能定义 endpoint/凭证；首次使用需 trust |
| 任意命令执行 | `cmd:` SecretRef 被写入配置 | 只信任用户自己配置目录下的 `cmd:`；`import` 默认剥离；执行时不过 shell（直接 execve，argv 数组形式） |
| 备份文件泄漏 | inplace 注入的备份里有用户原本的 key | 备份目录 0700；用完即删；崩溃恢复后也删 |
| 本地 Web 被跨站攻击 | 浏览器里其他页面打 127.0.0.1:8787 | Bearer token + Origin 校验 + 非简单请求 |
| DNS rebinding | 攻击者域名解析到 127.0.0.1 绕过同源 | 校验 `Host` 头必须是 `127.0.0.1`/`localhost` + Origin 白名单 |
| 供应链 | tool 描述符从社区来，带恶意 endpoint | 描述符不能带凭证与任意命令；导入第三方描述符时展示 diff 并要求确认 |

## 2. 密钥处理规则（硬性）

1. **配置文件里永远是引用，不是明文**（`plain:` 例外，写入时警告，且 UI 上标红）。
2. 明文只在**内存**中存在，且包在 `Secret` 里；取明文只有 `reveal()` 一个口子。
3. `reveal()` 的调用点全部可枚举（构造子进程 env、网关发上游请求）。加 lint 规则限制调用位置。
4. 所有面向用户的输出（stdout/stderr/日志/API 响应/Web）默认脱敏。**脱敏是默认，不是选项**。
5. 默认密钥后端优先级：OS 钥匙串 > `env:` > 加密文件 > 明文文件。
6. 导出配置默认剥离密钥；`--with-secrets` 需要二次确认并在输出里带显著警告头。

## 3. 文件权限

| 路径 | 权限 |
| --- | --- |
| `~/.config/newgate/secrets.json` | 0600 |
| `~/.local/state/newgate/daemon.json` | 0600 |
| `~/.local/state/newgate/backups/` | 0700 |
| sandbox 临时目录 | 0700，`mkdtemp` 创建 |
| 其他配置文件 | 0644 |

启动时校验，权限过宽则拒绝读取并提示修复命令（照抄 ssh 的做法，这个交互用户已经熟悉）。

## 4. 子进程边界

- 子进程 env 从**受控白名单**构造：继承父进程 env，删除描述符声明的 `unset` 变量，再叠加注入变量。不要「全量继承 + 无脑覆盖」。
- 不通过 shell 启动 tool（不用 `shell: true`），避免参数里的 `;`、`$()` 被解释。透传参数必须以 argv 数组形式原样传递——这也是透传正确性的要求。
- 不把密钥放进命令行参数（`ps` 可见）。只走 env 或文件。

## 5. 审计与可解释

- `newgate status --explain` 要能说清「这次用的 provider 来自哪一层配置」。安全事件排查靠它。
- 关键操作（改默认值、导入配置、启用 `plain:` 密钥、trust 项目配置）写审计日志到 `state/logs/audit.log`，仅追加。
- `newgate doctor` 检查项包含：文件权限、明文密钥、未 trust 的项目配置、残留备份、监听端口暴露面。

## 6. 不做的事

明确划出边界，避免范围蔓延：

- 不做多用户/权限系统。这是单机单用户工具。
- 不做密钥托管服务，不上传任何配置到云端。
- 不做「自动发现并接管系统里所有 AI CLI」这种全局 hook。所有接管都是显式的、一次一个进程的。
- 默认不开启任何遥测。真要加，必须 opt-in 且文档写清采集了什么。
